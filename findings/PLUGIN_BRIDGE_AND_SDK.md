# Plugin bridge and SDK traps

Places where the SDK looks like it works and silently doesn't, or where the obvious call is far too expensive. Each was measured on a real knowledge base (August–September 2026) or read from `app.asar`. Card-level behaviour is in [CARD_STATE_REFERENCE.md](CARD_STATE_REFERENCE.md), and powerup codes in [REMNOTE_POWERUP_CODES.md](REMNOTE_POWERUP_CODES.md).

## Storage

**The synced per-key limit is counted in UTF-16.** A scratch key accepted exactly 458,752 characters, the same for 1-, 2- and 3-byte UTF-8 alphabets: the ceiling is 896 KB of **UTF-16** (`JSON.stringify(v).length * 2`). A key that reads 50% full in UTF-8 is at the limit. Over it, **writes are rejected silently**: `flashcardHistoryData` sat over the ceiling for weeks while every write failed. `calibratePerKeyLimit` and `worstCaseBytes()` in `src/lib/synced_key_audit.ts` measure it. The plan for shrinking synced storage is [plans/STORAGE_PLAN.md](../plans/STORAGE_PLAN.md).

Plugin storage has **no deletion API**. Writing `null` does not free a key.

## Powerups and slots

**Built-in powerup membership can't be enumerated.** `powerup.taggedRem()` is reliable only for the plugin's own powerups. For RemNote's built-ins it returns a small fraction with no error: 3 Rems for Extra Card Detail on a KB holding thousands. `getTagRems()` on a Rem also omits built-ins, though it does list plugin powerups and plain named tags. To find Rems carrying a built-in:
- walk the scope and call `hasPowerup(code)` per Rem;
- filter on the synchronous snapshot fields first (`text`, `backText`, `children` cost no round trip), so only survivors pay for a call. `src/lib/empty_ecd_scan.ts` shows the pattern.

**A write to a retired slot is a silent no-op.** Once a slot is unregistered, `getPowerupProperty` still returns its stored value, but `setPowerupProperty` returns normally and changes nothing. RemNote only toasts *"attempted to setPowerupProperty for a slot which doesn't exist"*. Registering the slot again doesn't help: values belong to the slot's **definition Rem**, and re-registering mints a new one that masks the old values. Stranded values are readable but can't be written or cleared. Always probe one Rem and read it back before a bulk slot write.

**Pin To Sidebar is the Document powerup's `Status` slot.** The star sets the built-in Document powerup (`o`) hidden slot `Status` to `Pinned` (the enum is `Draft` / `Finished` / `Pinned`). `DocumentSidebar` (`s`) and `SavedDocuments` (`sd`) are not involved. From a plugin: `rem.setIsDocument(true)`, then `rem.setPowerupProperty(BuiltInPowerupCodes.Document, 'Status', ['Pinned'])`; unpin with `['Draft']`. Pass the slot name `'Status'`: the SDK maps it to the wire code.

**Disabled clozes are unreachable.** RemNote keeps them in the Rem field `dci` (an array of cloze ids). The SDK drops that field, the bridge has no accessor, and `getCards` is hard-wired to exclude disabled cards. `setEnablePractice(true)` does not clear `dci`. See [CARD_STATE_REFERENCE.md](CARD_STATE_REFERENCE.md).

## Reading Rems

**`rem.children` is lazy.** The bridge fills it from a cache that loads only when something opens or expands the Rem, so it is `[]` for any document not opened this session. `parent` is stored and reliable. Reliable reads, cheapest first:
1. Rems already in hand from `getAll()` or `getDescendants()`: group by `parent`, with zero extra calls.
2. One `rem.getDescendants()`, grouped by `parent`.
3. `rem.getChildrenRem()` for one Rem's direct children. Order is not guaranteed: use `positionAmongstSiblings()`.

**Card fields** (measured August–September 2026):
- Disabling a practice direction **removes** that card from `rem.getCards()`; its history survives, and re-enabling brings back the same record.
- A new, never-practised card has a real `nextRepetitionTime` (its creation instant), not null.
- `Card.lastRepetitionTime` is null even after several repetitions: derive it from `repetitionHistory`.
- `Card.createdAt` is per card and reliable. `Rem.createdAt` is not a baseline: a recreated or moved Rem can be younger than its cards.

**Tag instances list regardless of parent.** A tag Rem lists its tagged Rems in *All Tagged Bullets* whether or not they are its children, and a document queue already gathers a Rem's instances with all their descendants. Reparenting under a tag is a filing choice, never a discoverability or queue-scope one.

## Commands and UI

**Shortcut modifiers.** A plugin command's `keyboardShortcut` goes through the same `is-hotkey` parser as RemNote's own:
- `mod` = Cmd on Mac, Ctrl elsewhere;
- `cmd` / `command` / `win` = **Meta on every OS**, so `cmd+right` is Win+→ on Windows;
- `ctrl` = the physical Ctrl key, even on Mac;
- `opt` / `option` = Alt.

RemNote's built-in defaults are listed in [RemNote-Native-Shortcuts](../docs/RemNote-Native-Shortcuts.md), generated by `scripts/extract_remnote_shortcuts.py`.

**A second toast can vanish.** A toast raised while another plugin toast is still visible can be swallowed: the call succeeds and nothing shows. Don't raise a "working…" toast before a result that may follow within seconds. Report failures with `showMessageDialog` (`src/lib/message_dialog.ts`) and keep toasts for success.

## Build traps

**Never import from a widget file.** Every `src/widgets/*.tsx` is a webpack entry that calls `renderWidget(...)` when loaded. Importing a component from one runs that `renderWidget` inside the importing widget: the wrong widget renders, and React throws minified error #40 on deactivate. It only shows in the production build. Shared UI belongs in `src/components/` or `src/lib/`.

**New widget files need `npm run dev` restarted.** Webpack entries are globbed at startup.
